# 実装前に確定が必要な項目

設計書から仕様を抽出する過程で見つかった、**未定義または曖昧な点**。いずれも設計側の判断が要るため、このリポジトリで勝手に決めず `volanja/Dioryga_Design` に課題として提起する。

## 定義そのものが欠けているもの

| # | 項目 | 内容 |
|---|---|---|
| Q-1 | **`PROJECT` テーブルにカラム定義が存在しない** | 設計書の全ER図を通じて `PROJECT` は関連の端点としてしか登場せず、フィールドが一度も定義されていない。名前・説明・状態（進行中/完了/中止）・期間などが必要と思われるが未確定。**最も基本的なテーブルが未定義**であり、優先度が高い |
| Q-2 | **`SOFTWARE_INSTANCE.status` の語彙が未定義** | `status` 列は存在するが取りうる値の記載がない。DEVICE/PART_INSTANCE と同じ語彙でよいか（`building` や `repair` がソフトウェアに意味を持つか）が不明 |
| Q-3 | **スタックの論理DEVICEの `device_type`** | `DEVICE_STACK.logical_device_id` が指すDeviceは物理筐体を持たない（`configuration_id` は誰のものか）。`Physical` でも `Virtual` でもない性格であり、扱いが未定義（設計書8.6） |

## 型・表現の不整合

| # | 項目 | 内容 |
|---|---|---|
| Q-4 | `IMPORT_RUN.as_of` の型 | ER図では `string` だが、意味的には `datetime`（設計書23.7） |
| Q-5 | `serial_number` の一意性の範囲 | ベンダーをまたぐと衝突しうる。どの範囲で一意とみなすかが未確定。重複統合（M-4）と取込時の重複検出（I-4）の判定に影響する（設計書23.10） |
