# 実装前に確定が必要な項目

設計書から仕様を抽出する過程で見つかった、**未定義または曖昧な点**。いずれも設計側の判断が要るため、このリポジトリで勝手に決めず `volanja/Dioryga_Design` に課題として提起する。

## 解決済み

抽出時に見つかり、設計側で解消されたもの。記録として残す。

| # | 項目 | 結論 |
|---|---|---|
| ~~Q-1~~ | `PROJECT` にカラム定義が存在しなかった | **解決**（設計書5章）。`uid`/`code`/`name`/`description`/`currency`/`archived_at`/`closure_reason`。日付とサービス上の状態は持たず、`MILESTONE` から導出する |
| ~~Q-2~~ | `SOFTWARE_INSTANCE.status` の語彙が未定義 | **解決**（9.4.1）。`status` 列を廃止し `retired_at`（nullable datetime）に置換。インストール状態は `SOFTWARE_INSTALLATION` から導出する |
| ~~Q-3~~ | スタックの論理Deviceの `device_type` が未定義 | **解決**（8.6）。`device_type` に `Logical` を追加。論理側と物理メンバー側で何をどちらが持つかを表で規定 |
| ~~Q-4~~ | `IMPORT_RUN.as_of` の型が `string` | **解決**（23.7）。`datetime` に修正 |

## 未解決

### 定義・整合性

| # | 項目 | 出典 |
|---|---|---|
| Q-5 | **`serial_number` の一意性の範囲**。ベンダーをまたぐと衝突しうる。重複統合（M-4）と取込時の重複検出（I-4）の判定に影響する | 23.10 |
| Q-6 | **複数通貨の取り扱い**。`PURCHASE_ORDER` だけが `currency` を持ち、`MAINTENANCE_CONTRACT.amount`・`RECURRING_COST.amount`・`FIXED_ASSET.acquisition_cost` は通貨を持たない。v1は「1プロジェクト内は `PROJECT.currency` に統一」という運用前提で回避する | 5.4, 17.1 |
| Q-7 | **プロジェクトの予算**。年間コストダッシュボードは実績を計算するのみで、比較対象の予算を持たない。予算対実績を扱うかはスコープの判断 | 17.1 |
